## 在线演示

无需安装任何东西——打开在线版本，按下 **Run** 即可：

**https://code-pulse-dev.github.io/Micromouse-Car-Maze-Simulator/**

浏览器版与桌面版使用同一个 16 × 16 迷宫、同一套洪泛填充清扫逻辑、同样的专属走廊规则
和最短路径竞速。

## 快速开始

**方式一 —— 浏览器直接玩（零安装）**

1. 打开[在线演示](#在线演示)链接。
2. 保持默认的 **Explore 模式**，点击 **Run**。
3. 观看四车清扫；点击 **Reset** 后切换到 **Shortest Path 模式** 看竞速。

**方式二 —— 运行桌面端（Windows / Linux / macOS）**

环境要求：Python 3.10 或更高版本，带 Tkinter。无需任何第三方库。

```bash
git clone https://github.com/Code-Pulse-Dev/Micromouse-Car-Maze-Simulator.git
cd Micromouse-Car-Maze-Simulator
python maze_simulator.py
```

**方式三 —— 不用 Git 直接下载**

点击绿色 **Code** 按钮将仓库下载为 ZIP，解压后运行 `python maze_simulator.py`
（或直接双击 `index.html` 使用浏览器版）。

## 使用指南

### 模拟模式

**Explore 模式（探索模式）** —— 对应真实 Micromouse 比赛的第一阶段。每辆车：

1. 清扫自己的 8 × 8 象限，优先驶向最远的未访问区域。
2. 把感知到的每面墙写入自己的私有地图（真实迷宫不会被直接泄露给车）。
3. 象限清扫完毕后，沿**专属走廊**（其他车辆不得进入的私人通道）驶入自己的目标格并停下。
4. 输出到达用时、探索百分比、行驶步数和转弯次数。

**Shortest Path 模式（最短路径模式）** —— 对应比赛第二阶段。所有车辆开局即获得完整迷宫，
规划到目标的最短路线后直接竞速。这一模式回答的问题是：*迷宫已知后，车能跑多快？*

### 操作控制

| 输入 | 作用 |
|---|---|
| **Run / Pause** | 启动或暂停整个仿真。 |
| **Step** | 精确推进一步决策——适合逐格讲解算法。 |
| **Reset** | 所有车辆回到角落，地图清空。 |
| **模式选择** | 在 Explore 与 Shortest Path 之间切换（会重置对局）。 |
| **步长时间滑块** | 一步 = 一次前进或一次 90° 转弯，范围 100–400 毫秒。 |
| **Trails 勾选框** | 在迷宫上绘制每辆车的历史轨迹。 |

### 如何读懂洪泛值

洪泛填充会为每个格子计算：只经过**已知可通行**通道到达目标所需的最少前进步数。
目标格显示 0，相邻格显示 1，依次向外扩散。由于车辆的地图在行驶中不断成长，
数字会持续变化——开局时是对几乎空白地图的乐观猜测，结束时则是已发现迷宫的真实最短距离。
不可达的格子保持空白。

### 迷宫工具

- **编辑墙壁** —— 点击格子边缘即可切换墙（两侧同步更新，保持一致）。
- **保存 / 加载迷宫** —— JSON 文件存放在 `saved_mazes/`。
- 项目自带的迷宫就是真实比赛迷宫，包含队伍实测的墙体修正。

### 硬件面板

桌面端可通过 USB（COM 口 + 波特率）连接真车。它会完成握手、显示车名，并以下列任意格式
读取真实电池电压：

- `BAT:7.86V`（伏特）· `BAT:87`（百分比）· `{"voltage": 7.86}`（JSON，兼容毫伏值）

充电状态由电压推导：高于 8.2 V 显示*电量充足*，低于 6.8 V 显示*需要充电*（2S 锂电池组）。
未连接车辆时如实显示 *Not Connected*。

## 车辆代码适配器

桌面端可以用**你自己的**控制器替换内置清扫逻辑（按车独立选择）：

1. 在 Car Code 面板中选择一个车位。
2. 点击 *Upload Code Folder*，选择你的代码文件夹。
3. 模拟器会在 `car_codes/` 中匹配对应的适配器——或直接加载你文件夹里的
   `CarController.py`——并逐步运行。

**适配器契约。** `CarController` 类每步接收一个状态字典（位置、朝向、传感器读数、
私有地图），返回一个移动指令：`forward`、`left`、`right` 或 `turnback`。
请以 `car_template.py` 为起点编写。

**比赛公平性由模拟器保证，而不是靠你的代码自觉。** 象限限制、专属走廊与碰撞规则对所有
适配器一视同仁，任何有缺陷或作弊的控制器都无法破坏比赛。

项目附带两个现成适配器——队伍真实车辆的忠实移植：

| 适配器 | 移植自 | 行为 |
|---|---|---|
| `ESP32-S3 Micromouse Adapter` | ESP32-S3 车辆固件策略（ToF 传感器、MPU6050 转向） | 与真车移动序列完全一致 |
| `TQD Micromouse JS2 Adapter` | TQD 车辆 MicroPython 策略（右手搜索、等高线导航） | 与真车移动序列完全一致 |

在标准迷宫上，两个适配器均能逐步复现内置清扫路径——已由回归脚本验证——因此仿真结果
真实反映了实车表现。

## 模拟原理

- **迷宫模型** —— 16 × 16 网格；每格存储四个方向的墙位（北/东/南/西）。外边界永远封闭。
- **比赛地理** —— 四个 8 × 8 象限，每辆车一个起始角和一个目标
  （`(0,0)→(7,7)`、`(15,0)→(8,7)`、`(0,15)→(7,8)`、`(15,15)→(8,8)`），
  另有四条专属走廊保证四车同时运行互不相撞。
- **决策循环（每车每步）** —— 感知 → 将墙写入私有地图 → 在已知地图上洪泛填充 →
  选择最优邻格（平局时优先直行）→ 转向并前进一格。
- **计时** —— 比赛用时 = 步数 × 单步时间。里程统计每次前进一步（含重访）；
  探索百分比统计象限内访问过的不同格子数（共 64 格）。

## 验证测试

仿真逻辑由无界面回归测试验证，每次修改都会断言：

- Explore 模式下每辆车覆盖其象限 **64 / 64 格（100 %）**。
- 每辆车都经由自己的走廊完赛——任何车辆都不会进入其他车的专属走廊。
- 最短路径模式均以最优路线到达目标。
- 两个车辆代码适配器在标准迷宫上逐步复现内置清扫路径。

## 常见问题

**洪泛值为什么一直在变？**
车辆只知道它感知过的墙。代价地图每步都在已知地图上重新计算，因此随着迷宫被学习，
数值会越来越准、越来越短。

**两辆车会不会相撞？**
不会。探索期间每辆车都被限制在自己的象限和专属走廊内，四条同时进行的路线互不共享格子。

**浏览器版有车辆代码适配器和硬件面板吗？**
没有——它们需要真实文件系统和串口，因此只存在于桌面端。浏览器版涵盖迷宫、洪泛填充、
两种比赛模式和全部可视化效果。

**是否只能用某一个迷宫？**
不是。生成、编辑或加载任意 16 × 16 迷宫，同一套逻辑照样适用。
